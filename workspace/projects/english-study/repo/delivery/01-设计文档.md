# English-study 设计文档

## 1. 文档目的

本文档用于描述 `projects/english-study/repo` 当前交付形态下的系统目标、功能范围、核心组件、部署约束和已知限制，作为研发、测试、部署和后续验收的统一参考。

## 2. 产品定位

English-study 是基于 Label Studio 定制的英语学习数据标注与复核平台。本次交付基于一个裁剪后的工作仓库，重点保留以下能力：

- 项目创建与项目配置
- 标注与复核流程
- 任务导入、结果导出
- 模型后端连接、预测接入与预测辅助标注
- 与当前仓库仍然匹配的本地文档与源码运行入口

本次交付不承诺完整覆盖上游 Label Studio 的全部产品面，而是以当前仓库中仍保留、仍能诚实描述的能力为准。

## 3. 交付目标

- 交付一个可继续演进的英语学习标注平台代码基线
- 保留模型接入与预测辅助相关能力，不在本轮文档清理中误删模型能力
- 明确当前可支撑的运行入口、配置项与部署方式
- 为后续修复源码异常、补充前端或运行验证提供文档基础

## 5. 系统结构

### 5.1 后端

后端以 Django 为核心：

- `label_studio/manage.py` 作为 Django 管理入口
- `label_studio/server.py` 作为 CLI/服务入口
- `label_studio/core/settings/base.py` 负责基础配置
- `label_studio/projects/`、`label_studio/ml/` 等模块提供项目与模型相关能力

### 5.2 前端

当前仓库仍保留以下前端结构：

- `web/apps/labelstudio/`：应用壳层
- `web/libs/editor/`：编辑器相关前端代码
- `web/libs/datamanager/`：任务数据管理相关前端代码

需要注意的是，仓库中前端树并不完整，因此当前设计文档只对已确认保留的代码结构负责，不对缺失源码对应的完整页面行为作超范围承诺。

### 5.3 模型集成

模型能力是当前交付明确保留的部分，不应在本轮清理中被删除。当前文档与配置保留了以下模型相关概念：

- Connect Model
- Live Predictions
- Imported Predictions
- Interactive preannotations
- 模型训练、测试请求和模型管理动作

## 6. 运行与配置设计

### 6.1 Python 与依赖

`pyproject.toml` 当前显示：

- 包名保持 `label-studio` 以兼容现有入口
- Python 版本范围为 `>=3.8,<4`
- 入口脚本为 `label-studio = "label_studio.server:main"`

### 6.2 基础环境变量

根据 `label_studio/core/settings/base.py`，部署中重点关注：

- `HOST`
- `DEBUG`
- `BASE_DATA_DIR`
- `DJANGO_DB`
- `POSTGRE_*`
- `MYSQL_*`

### 6.3 端口与数据目录

- 内部默认端口为 `8080`
- 默认数据目录由 `BASE_DATA_DIR` 或运行时数据目录决定
- 默认数据库可落到本地 SQLite，也支持 PostgreSQL / MySQL 配置

## 7. 角色与使用流程

平台典型角色包括：

- 管理员：建项目、配模板、接模型、导任务、配成员
- 标注员：领取任务、执行标注、提交结果
- 审核员：执行复核、退回问题样本、维护一致性

标准业务流程为：

1. 创建项目
2. 配置标签与项目设置
3. 接入模型（如需要）
4. 导入任务
5. 执行标注
6. 执行复核
7. 导出结果
