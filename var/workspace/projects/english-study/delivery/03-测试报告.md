## 5. 关键验证结论

### 5.1 文档与身份面

当前仓库已完成以下收口：

- `README.md` 已明确这是 English-study 的裁剪工作仓库
- 本地项目设置文档已改为自包含写法
- `pyproject.toml` 中作者信息已改为 `English-study maintainers`
- 模型后端、预测和交互式预标注等说明仍然保留

### 5.2 运行入口

当前可以确认的入口包括：

- `label_studio/manage.py`
- `label_studio/server.py`
- `pyproject.toml` 中的脚本 `label-studio = "label_studio.server:main"`

### 5.3 当前失败项

#### 失败 1：`base.py` 语法异常

执行：

```bash
python3 -m py_compile label_studio/core/settings/base.py
```

结果：

```text
SyntaxError: '[' was never closed
```

说明：

- 当前 `label_studio/core/settings/base.py` 很可能存在文件截断或内容损坏
- 在该问题修复前，完整 Django 设置加载不可视为可信

#### 失败 2：`server.py` 存在同类异常风险

静态抽样显示 `label_studio/server.py` 在 `_create_project(` 一段附近也存在截断迹象，说明服务入口文件同样可能不完整。

### 5.4 未具备项

当前环境无法直接导出 Word：

- `python-docx` 不可用
- `pandoc` 不可用
- `soffice` / `libreoffice` 不可用

因此本轮交付先提供 Markdown 文档版本。

## 6. 风险评估

| 风险                    | 级别 | 说明                         |
| ----------------------- | ---- | ---------------------------- |
| Django 设置文件疑似损坏 | 高   | 直接影响服务启动             |
| 服务入口文件疑似损坏    | 高   | 直接影响 CLI / server 启动   |
| 前端源码不完整          | 中   | 影响页面可达性验证           |
| 当前无 Word 导出工具链  | 低   | 影响文档格式，不影响源码修复 |

当前版本可以作为“文档与代码基线整理版”提交并回滚，但不能宣称为“已完成运行验证的可发布版”。在修复 `base.py` 与 `server.py` 之前，不建议把该版本作为最终可运行交付物。
